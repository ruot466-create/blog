# 博客写作与维护

这份说明供自己维护博客使用，不会作为文章发布。

## 内容怎么放

| 栏目 | 适合放什么 | 可用模板 |
| --- | --- | --- |
| 成长 | 阶段总结、想法的变化 | `templates/growth.md` |
| 技术 | 项目、学习实践、排错过程 | `templates/technical.md` |
| 音乐 | 练琴、曲子、乐理 | `templates/music.md` |
| 生活 | 游戏、读书、日常 | `templates/post.md` |

每篇文章选一个 `category`。标签用来细分主题，如 `JavaScript`、`AI`、`吉他`、具体游戏名。不要把同一个意思重复写进分类和标签。栏目名称、顺序与首页介绍集中在 `src/constants/blog.ts`。

首页会展示四个栏目；没有已发布文章的栏目显示「待更新」，不会链接到空归档。侧边栏只统计有内容的栏目。开发预览会包含草稿，正式构建会排除草稿。

## 接下来值得写的三篇

1. **第一份阶段回顾**：从开博到现在真正完成了什么；挑一件事展开，附一个能看到的成果。无需凑成周更或月更。
2. **这个博客的一次实际修改**：例如音乐播放器换页后重置的问题。先对照 `docs/decisions-blog.md` 的 D11，再自己复现当前行为、理解关键改动，写清哪些部分借助了工具。
3. **第一份练琴对照**：选自己实际在练的片段，记录卡点、练法，有录音就附上。没有练习经历时先留着，不为填满栏目编内容。

`about-gpt.md` 目前只有图片署名，继续保留草稿。动笔时先选一个自己实际遇到的问题，例如一次回答哪里有帮助、哪里需要核验。写具体例子，比笼统评价 GPT 更容易讲清楚。

## 写一篇文章

运行 `pnpm new-post 文件名`，或者把模板复制到 `src/content/posts/文件名.md`。模板中的日期占位符需要替换成实际日期；新建脚本会自动填写日期。

新文章默认 `draft: true`。补好标题、日期、摘要、分类和正文，检查图片来源和链接，再手动改成 `draft: false`。封面可选，不必每篇都配图。

## 维护入口

- `src/content/spec/about.md`：长期自我介绍。
- `src/content/spec/now.md`：当前状态；每次修改同步更新正文里的日期。
- `src/content/spec/uses.md`：实际使用的工具。
- `src/content/posts/`：文章与草稿。
- `public/images/`：文章封面与图片。

## 发布前检查

1. `pnpm check`：检查代码和内容结构。
2. `pnpm build`：生成网站和站内搜索索引。
3. `pnpm preview`：查看正式构建的效果，确认文章、分类和图片正常，草稿没有出现。

提交并推送 `main` 会触发 `.github/workflows/deploy.yml`，部署到 Cloudflare Workers。运行本地预览不会自动发布。
